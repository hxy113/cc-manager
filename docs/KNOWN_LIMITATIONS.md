# 已知限制

本文只列当前代码中仍然存在、能够从实现推导或已验证的限制。历史上已经修复的问题应写入 `CHANGELOG.md`，不要继续留在这里。

## 高优先级

### 多进程不互斥

备份与恢复只有进程内互斥。同时启动两个 cc-manager 实例时，它们会共用 `~/.cc-manager/backup-workspace`、配置和元数据，仍可能互相覆盖工作区状态。

建议增加文件锁，并在第二个实例启动时给出明确提示。

### 配置与元数据不是原子写入

`meta.json` 和 `config.json` 使用同步整文件覆盖。进程在写入中断时可能留下损坏 JSON；读取失败会静默回退默认值或空对象，后续保存可能覆盖原内容。

建议使用“临时文件 + flush + 同目录原子替换”，并保留损坏文件副本。

## 性能与容量

- 自动本地同步会完整读取并哈希每个当前会话；它显著减少重复写入和占用，但仍使用同步文件 API，大数据集扫描期间会阻塞事件循环。
- 固定 4 MiB 分块非常适合 JSONL 末尾追加；若文件头部或中间插入内容，后续分块边界会整体移动，去重率会下降。当前未实现 Rabin/FastCDC 一类内容定义分块。
- 遵循“只移入回收站、不物理删除”原则，内容对象仓库没有垃圾回收；备份空间只会增加。未来若增加保留策略，必须默认移动整份旧仓库到外部回收站，不能就地删除对象。
- Claude `getSessions` 会逐个完整读取项目内所有 JSONL；Codex 每次列项目、列会话或定位会话时会递归扫描并解析全部文件。
- 文件 API是同步的；大目录或超大会话会阻塞 Express 事件循环。
- 前端一次渲染整个项目的会话列表和所选会话正文，没有分页或虚拟滚动。
- 内容搜索会再次完整扫描会话；用户正则没有执行时限，复杂表达式可能长时间占用进程。
- 编辑请求受 Express 10 MB JSON 限制；大于该大小的原始会话无法通过内置编辑器保存。

建议优先增加基于路径、mtime、size 的摘要索引和缓存，再考虑 worker thread、流式解析与虚拟列表。

## 备份与恢复

- WebDAV 只有上传与连接测试，没有远程历史、下载或恢复。
- 备份只包含 Claude/Codex 会话目录和 `meta.json`，不包含 `config.json`、CLI 设置、凭据和其他状态。
- Git 初始化空提交会出现在历史列表，但它不含会话，选择恢复会失败。
- 本地历史只识别名称可解析为时间且含特定目录、`.diff-ref` 或 `.sync-manifest.json` 的文件夹；任意命名的手工副本不会显示。
- 新同步快照的对象仓库与快照清单必须一起迁移；只复制 `auto-*` 清单目录而漏掉同级 `.cc-manager-sync/objects/` 将无法恢复。
- 若确实要清空某一 CLI 的全部会话，应保留其空源目录再运行同步；直接移走整个源目录会被当作异常并拒绝发布，以防误生成批量删除快照。
- 恢复前安全快照始终写入默认本地根目录，不跟随 `localBackupDir`。
- `all` 模式是部分成功语义：一个目标失败时其他目标仍可能完成，顶层 `ok` 为 false，调用方必须检查 `results`。
- `lastBackupAt` 表示“至少一个目标成功”，不代表所有配置目标都成功。
- Git 推送失败但本地 commit 成功后，如果下一次快照没有文件变化，`doGitBackup` 会按“无变更”跳过，当前不会单独重试尚未推送的 commit。
- `branch` 配置只作为 push ref 使用，不会自动创建或切换内部工作区分支；配置为不存在的分支会导致推送失败。
- 当前测试没有对用户真实目录执行破坏性恢复；`full` 语义主要由临时目录单元测试覆盖。

## 平台与集成

- 浏览、搜索和 `fs.cpSync` 备份大体可跨平台，但“在 CLI 中打开”使用 Windows `cmd /k`，其他系统不可用。
- 删除回收目录按 cc-manager 代码位置的上两级计算，不是用户可配置项；全局 npm 安装时位置可能不符合预期。
- Claude Code 与 Codex CLI 的本地 JSONL 格式不是 cc-manager 控制的稳定 API；上游升级可能使标题、消息统计、预览或 Fork 失效。
- CLI 可执行路径在服务启动时解析一次；PATH 或安装状态变化后必须重启。
- 自动备份定时器也只在启动时创建；在设置里修改周期后必须重启。

## API 与产品体验

- API 没有版本前缀，也没有自动生成的 schema/OpenAPI。
- 参数校验不完全统一；备份/恢复运行时失败常用 HTTP 200 + `ok:false`，其他接口使用 4xx/5xx。
- 配置 API只做字段白名单，尚未完整验证 URL、分支名、目录可写性和数值范围；UI 约束不能替代 API 校验。
- `showHidden` 只能显示仍在磁盘且元数据为 hidden 的会话，不能显示已经移动到 trash 的会话。
- trash 没有浏览、还原或清理 UI。
- 内容搜索只返回匹配次数，不返回片段，也不在正文中高亮。
- UI 是单个 `web/index.html`，后端备份逻辑集中在单个大文件，修改和测试隔离成本较高。

## 安全与隐私

- 服务没有用户认证，安全模型依赖“只监听本机 + Host 校验 + 无 CORS”。不支持直接暴露到局域网、公网或通用反向代理。
- 备份包含完整对话和工具输出，可能含路径、命令、源码或密钥；Git 仓库和 WebDAV 目标应按敏感数据管理。
- Git token 被拼进一次性 HTTPS push URL；虽然不会写入配置，操作系统进程查看工具仍可能在短时间内观察到命令参数。
- Markdown 导出不做敏感信息脱敏。
